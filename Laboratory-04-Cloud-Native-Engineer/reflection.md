# Reflection

## Laboratory 04: Cloud-Native Engineer

This laboratory activity gave me a better understanding of Docker and its role in cloud-native application development. I learned that containers provide a practical way to package and run applications with the files and dependencies they need. This makes applications easier to manage and deploy across different environments.

One of the main lessons I learned was the difference between virtualization and containerization. Virtual machines use separate guest operating systems, while containers share the host operating system kernel. Containers are therefore lightweight and can start faster. This difference explains why container technology is widely used in modern software development and cloud infrastructure.

During the activity, I practiced several Docker commands, including `docker --version`, `docker info`, `docker pull`, `docker run`, `docker ps`, `docker stop`, and `docker start`. I used an Nginx image to create and manage a web server container. I was able to run the container on port 8080, access the Nginx welcome page, stop the container, and start it again. These steps helped me understand the basic lifecycle of a Docker container.

I also realized that learning Docker requires attention to command syntax and the status of containers. At first, it was challenging to remember which command should be used for downloading an image, creating a container, viewing running containers, or managing stopped containers. By practicing each command and checking the results, I became more familiar with the process.

Overall, this laboratory activity improved my technical knowledge of containerization and cloud-native infrastructure. It showed me how Docker can simplify application deployment, improve portability, and support efficient system administration. The skills I gained from this activity will be useful in future cloud computing activities and in developing my career as an IT professional.
